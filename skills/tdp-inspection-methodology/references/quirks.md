# 数据口径陷阱与统计假象

**引用任何数字前先过一遍这张表。** 这些坑会让结论「看起来很严重」但其实是机制产物，
或者让你把残缺数据当全量报出去。

---

## 口径规则

### Q1 · 统计必须用聚合接口，不能用明细列表累加
（前提是聚合接口可用，见 Q6）
明细列表受分页限制，累加会得到被截断的数字。
**规则**：统计一律用 `tdp_log_search action=terms` 的 `global_total` / `global_percent`；
明细列表只用于取证单条告警的五元组和载荷。

### Q2 · 聚合接口的 `size` 默认只有 10
不显式调大，你拿到的是 TOP 10 而不是全貌，算出来的占比全错。
**规则**：做统计时显式设 `size`（建议 200–1000）。该工具**不支持 `page_size`**。

### Q3 · 同一会话命中多条规则 = 多条告警，不是多次攻击
一次连接可能同时命中协议特征、家族特征、行为特征等多条规则。
**规则**：按会话（同 `id`，或同五元组 + 威胁名 + 时间邻近）去重后再统计「攻击次数」。
告警计数反映的是**规则命中次数**。

### Q4 · 同一 IP 因资产身份变化会出现多行
资产识别随时间演变，同一 IP 可能以不同资产名出现多次。
**规则**：统计「受影响主机数」按 IP 去重；呈现时保留资产名差异（它本身反映资产识别的演变）。

### Q5 · 列表接口默认只返回 20 条，且不会自动翻页 —— **最容易造成事实性错误的一条**
实测：`service_list` 默认返回 20 条，而响应里 `page.total_num = 445`、`total_pages = 23`。
只取到 4.5%，若把 20 当成资产总数写进报告，整份攻击面分析作废。
**规则**：每个列表调用必须读 `page.total_num` / `page.total_pages` 并循环翻页取全；
报告中的资产数字一律用 `total_num`，不是本次取回的条数；取不全的必须标 `partial` 进 coverage_gaps。

### Q6 · 聚合接口可能整个不可用（服务端能力缺失，非参数问题）
实测某些 TDP 部署上 `tdp_log_search action=terms` 返回服务端 Spring bean 缺失错误
（`LogTermService` 未加载），**与时间窗、聚合字段、日志类型都无关**，换参数无用。
**规则**：聚合要有主备。主用 `terms`；不可用时降级到设备自带的事件智能聚合、
或主机级聚合（`alert_host_list`）。降级后**信噪比分母是估算值**，报告中必须声明口径，
不得当成精确占比呈现。

### Q7 · 资产数字带时间窗语义
TDP 资产类接口强制时间窗，查到的是「**该窗口内在网络上出现过的**资产」，不是全量台账。
**规则**：资产用长窗；任何资产数字都必须标注其窗口；不要把短窗结果当「资产总数」。

## 统计假象清单

### F1 · 公网段内网 IP 被误判为境外攻击者
设备按公网 IP 库做地理定位。客户若用公网地址段做内网，这些地址会被标成境外攻击者。
**规则**：见「境外攻击者」先核对该 IP 是不是客户自己的资产。是 -> 排除地理结论并在报告中说明。

### F2 · NAT 回环让自有地址同时出现在攻击源和目标两侧
源与目标是同一个客户公网地址时，观测到的是 NAT 回环流量。
**规则**：标记为回环，不计入外部攻击统计。

### F3 · 反向代理 / NAT 把入站攻击系统性记成横移
设备部署在代理之后时，所有外部攻击的源都变成代理的内网 IP。
**规则**：比对 `net.real_src_ip` 与 `net.src_ip`；不一致则真实源取前者、方向重标为入站。
**这一条会整片判错，是最需要主动检查的口径问题。**

### F4 · 扫描器把告警量灌爆，让某主机「看起来」是头号受害者
一台扫描器能瞬间产生海量告警。
**规则**：看告警量 TOP 主机时先分清它是**攻击发起方**还是**受害者**
（看方向 / 攻击阶段 / 主机威胁态）。发起横移的源 != 失陷主机。

### F5 · 总体态势等级受可调阈值影响
等级由客户可配置的阈值算出，可能与实际发现不符。
**规则**：呈现矛盾 + 给复核建议，不盲从也不擅自改写。

### F6 · `Threat Result = Unknown` 不等于「没成功」
旁路检测无法确认结果时返回 unknown。
**规则**：unknown 的高危利用要结合目标补丁状态与后续是否出现横移／外联间接判断，
不能简单当「未成功」放过。

### F7 · 主机威胁态四项全绿 != 无风险
主机威胁态反映的是「**是否被攻陷**」，不反映「是否被攻击」或「是否有暴露面」。
**规则**：全绿的主机仍可能有大量攻击探测和暴露面问题，要单独看攻击面维度。

### F8 · 设备原生图表可能含伪切片
部分统计图会把「总计」当成一个分类画进饼图，导致各分类相加不等于总数。
**规则**：**一律引用正文/接口返回的数值，不引用图表百分比**。图表只作配图。

### F9 · 三个检测引擎可能不同步
TI / AI / Signature 三个引擎各自更新，可能只有其中一两个是新的。
**规则**：分别检查三个版本时间，不要看到一个是新的就判定「引擎正常」。
