# Session 话术 + 定时任务

## 先说清楚：Session 不是能「建」的东西

Flocks 官方文档里 Session 是**你和 Rex 的任务对话空间**，不是可配置的持久对象——
没有「新建一个巡检 session 模板」这种操作。所以「建好 session」实际是两件事：

1. **一段发起巡检的粘贴话术**（下面 §1、§2）
2. **把它转成 Task Center 定时任务**，让日更无人值守跑（下面 §3）

顺带：Session 的其他入口（Agent 页、Workflow 页开的 Rex 对话）也都会归到 Session Management 里，
所以你在 Workflow 页调试的对话，回头能在会话列表找回来。

---

## §1 日更巡检 · 手工补跑

定时任务正常跑的话你不用管。以下情况才手工发起：昨天任务挂了要补、临时想看某台设备、
或者验证 workflow 改动。

```text
用 tdp_daily_watch 工作流跑一次 <设备名> 的每日速览，回看窗口 24 小时。
结果推到 session_id: <你的值班群 session_id>。
```

指定日期补跑：

```text
用 tdp_daily_watch 跑 <设备名>，回看窗口 48 小时，先不要推送，我看完再决定。
```

## §2 深度巡检 · 按需发起

PoV 收尾、周期性安全回顾、客户交流前取数时用。**它有人审硬停**，跑到第 6 节点会停下来等你裁决，
所以别在赶时间的时候发起。

```text
用 tdp-inspection 工作流对 <设备名> 做一次深度巡检。

客户：<客户名>
威胁窗口：30 天
资产窗口：90 天
pov_mode：B
```

**`pov_mode` 必须显式给，不要让它猜**：
- `A` = PoV 期间我方做过模拟攻击/投放样本
- `B` = 纯真实流量旁路监听

判错会让整份报告的定性系统性偏掉——模式 B 下没有「我方测试」这一档，
一批整齐的失败 Exploit 就得归到「客户环境里的外部扫描」而不是「我们打的」。

跑到硬停时，Rex 会给你两栏清单（【需你裁决】只放定性存疑项，【客观项】列出供核对不阻塞）。
裁决完它才成文。

## §3 建定时任务（日更真正落地的地方）

先在 session 里手工跑通一次 `tdp_daily_watch`，确认产物正常，再转定时：

```text
把 tdp_daily_watch 配成定时任务：
- 每天 08:00 执行
- 设备：<设备名>
- 回看窗口 24 小时
- 结果推送到 session_id: <值班群 session_id>
- 单个工具失败不要中断整个任务，记进 coverage_gaps 继续跑
```

**最后一条别省。** 定时任务因为单点失败就中断，等于那天没有巡检，而且往往没人发现。

## §4 拿到 session_id（推送的前提）

推送靠 `session_id` 定位目标 IM 会话。先在**目标群里**（企微/飞书/钉钉，机器人已入群）问一句：

```text
你的 session_id 是多少？
```

Rex 会返回。或者在该 IM 会话里发 `/status`，能看到绑定的 Session / Agent / 模型 / 渠道。

拿到之后写进定时任务描述里，无人值守跑的时候才知道发给谁。

**两个坑**：
- 目标 IM 会话一旦跑过 `/new`，会重新绑定一个新 Session，**旧 `session_id` 就失效了**。
  推送突然没了先查这个。
- `session_id` 是路由标识，发敏感内容前确认它确实是你要的那个群——巡检简报里有内网 IP 和主机名。

## §5 常用 `/` 命令

| 命令 | 用途 |
|---|---|
| `/skills` | 确认 `tdp-inspection-methodology` 已被识别 |
| `/skills refresh` | 装完 skill 后刷新 |
| `/workflows` | 确认两个 workflow 都在 |
| `/tasks` | 看定时任务状态 |
| `/status` | 看当前会话绑定的 Session / Agent / 模型 / 渠道 |
| `/compact` | 长会话压缩上下文 |
| `/help` | 当前入口支持的全部命令（各入口略有差异） |

## §6 让 Rex 直接读方法论（不跑 workflow 时）

有时候你只是想让 Rex 帮你看一批已经导出的 TDP 数据，不需要走完整 workflow：

```text
载入 Skill tdp-inspection-methodology，帮我研判这批 TDP 告警。
pov_mode 是 B（纯真实流量，我方没做过模拟攻击）。
存疑的标 pending_review，不要替客户拍板。
```

最后一句别省——不加的话 LLM 倾向于把每条都给个确定结论，而定性拍错是巡检最危险的错误。
